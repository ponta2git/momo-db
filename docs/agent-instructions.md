# エージェント向け規約の保守

AGENTS.md、関連規約、repository skill を追加・変更するときに使う。目的は、共有 DB と consumer の契約を守りながら、依頼に必要な情報と完了条件を迷わず見つけられる状態を保つことである。

## 指示を置く場所

- `AGENTS.md` には、この repository の所有範囲、作業別の参照先、実行範囲、完了・PR の判断基準を置く。
- DB の変更・検証・適用・復旧の規範は `development.md`、通知の業務契約は `discord-notifications.md` に置く。同じ手順を複数の文書へコピーせず、正本の該当節へリンクする。
- README はセットアップとコマンドの入口、`docs/ops/` は特定の運用手順、ADR は判断と変更履歴、`docs/plans/` は個別案件の範囲・合意・受け入れ条件を扱う。過去の手順には後継の参照先を示す。
- 一度の作業にだけ必要な対象 commit、環境、受け入れ確認の結果は、その作業の Issue / PR / 計画に置く。個別案件の承認を、将来の本番操作への包括承認として残さない。

## 残す指示の基準

望む結果、守る制約、完了を示す根拠を具体的に書く。ツールを使う順序は、migration の生成順や承認・preflight のように、順序自体が正しさを保証する場合に定める。

各指示には適用条件を付ける。schema 変更に必要な全文確認を誤字修正へ広げず、通知の更新境界を一般の DB 作業へ広げない。「必ず」「禁止」「承認待ち」を追加するときは、対象の操作と守るデータ・契約を明確にする。停止が必要なら、止める操作、判断に足りない情報、独立して進められる範囲を示す。

検証は、変更した振る舞いと失敗した場合の影響に合わせる。DB の履歴不変性、生成と custom SQL の分離、データ保持、consumer 互換性、本番 approval / preflight は、この repository の具体的な制約として維持する。一般的な「念入りにテストする」という指示を重ねない。

モデルの得意不得意を補う指示は、実際の失敗例に対して効果を確認してから残す。モデル名・推論量・常時の並列委譲・実行環境の共通ルールを repository の必須条件にせず、複数モデルで使える契約にする。

## Skill を追加する場合

繰り返し使う固有のワークフローと、再利用する script・参照資料がある場合に検討する。既存文書への案内だけで足りる作業は AGENTS.md の参照先で扱う。

description は「何をするか」と「どの作業で使うか」が伝わる短い文にする。例えば migration 用なら「migration の追加・変更、適用計画のレビュー」を条件にし、「DB に関係する作業すべて」まで広げない。本文は必要な手順・資料への入口にし、該当する資料だけを読む構成にする。Skill に既存の規範を複製しない。

## 変更の確認

追加した文章の長さよりも、必要な規約へ到達できるか、不要な読込みや確認待ちが増えないか、既存の保護条件を失っていないかを確認する。参照リンクとコマンドを実ファイルに照合し、例えば次の依頼で読む文書・実行範囲・完了条件を追う。

| 代表的な依頼 | 期待する判断 |
| --- | --- |
| README の誤字修正 | 該当箇所・リンク・差分を確認して完了。DB 接続や migration の生成は不要 |
| 通知 ID の変更 | 共有通知契約と利用側への影響を確認し、build と通知契約で要求する検証を行う |
| column 追加と backfill | development.md を全文確認し、schema / custom migration の分離と必須 gate を守る |
| 専用 DB テストの失敗修正 | 隔離条件を確認し、修正・再実行・自身の一時資源の後始末まで進める |
| 適用済み migration の不具合 | 適用済み履歴を保持し、新しい forward migration で修正する |
| 本番接続先の更新 | 接続先更新手順へ進み、対象 commit の承認と preflight を維持する |
| ADR・旧計画と現行手順の差 | 後続の決定と正本を照合する。解消できない矛盾に依存する操作だけ止める |
| consumer の受け入れ確認が残る PR | 残作業を示し、`Refs` を使う。merge で完了する場合に `Fixes` を使う |

これは規約のレビュー観点であり、文書変更のたびに実 DB 操作を実行する指示ではない。実作業で過剰な読込み・不要な停止・検証漏れが起きたら、原因となった指示を修正し、この例も更新する。
